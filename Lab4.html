Module 01: Dynamic Arrays

Allocate arrays at runtime when size isn't known at compile time

💡 Key Concepts

  • Runtime Sizing: Array size determined during execution
  • Heap Memory: Allocated on heap, persists until explicitly deleted
  • Allocation: int* arr = new int[size];
  • Deallocation: delete[] arr; — must use delete[] for arrays!
  • 2D Arrays: Use pointer-to-pointer (int** matrix)
  • Memory Leak: Forgetting delete[] causes memory to never be freed
STATIC ARRAYS
int arr[100];
  • • Size fixed at compile time
  • • Stack allocated
  • • Automatic cleanup
  • • Fast but inflexible
DYNAMIC ARRAYS
int* arr = new int[n];
  • • Size set at runtime
  • • Heap allocated
  • • Manual delete[] required
  • • Flexible, can resize

Module 02: Namespaces & Separate Compilation

Organize code into logical modules and prevent naming conflicts

💡 Key Concepts

  • Namespace: Group related code: namespace MyNS { ... }
  • Access: MyNS::function() or using namespace MyNS;
  • Nested (C++17): namespace A::B::C { }
  • Alias: namespace Short = Very::Long::Namespace;
  • Header files (.h): Declarations shared across files
  • Include guards: #ifndef / #define / #endif prevents multiple inclusion
File Type Purpose Contains
.h Header Declarations Class definitions, function prototypes
.cpp Source Implementation Function bodies, method definitions
.o Object Compiled code Machine code (intermediate)

Module 03: Streams & File I/O

Read from and write to files using C++ stream classes

💡 Key Concepts

  • ofstream: Output file stream for writing (#include <fstream>)
  • ifstream: Input file stream for reading
  • fstream: Bidirectional file stream
  • stringstream: String-based stream for parsing (#include <sstream>)
  • Always check: if (!file) { error handling }
  • Close files: file.close(); (or let destructor handle it)
Mode Flag Description
Read ios::in Open for reading (default for ifstream)
Write ios::out Open for writing (creates/truncates)
Append ios::app Append to end of file
Binary ios::binary Binary mode (not text)

⚠️ Common Mistakes to Avoid

  • Using delete instead of delete[] for arrays
  • Forgetting to delete dynamic memory (memory leaks)
  • Deleting 2D array in wrong order (rows first, then array of pointers)
  • Not checking if file opened successfully before using
  • Forgetting to close files (though destructor handles it)
  • Missing include guards in header files
  • Using using namespace in header files (pollutes global)
  • Not using reinterpret_cast for binary I/O
  • Mixing text and binary modes incorrectly
  • Accessing deleted/freed memory (dangling pointer)
